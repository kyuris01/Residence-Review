# 빛가람 아파트 리뷰·데이터 요약 지도

전남 나주 빛가람동으로 이주를 검토하는 사람이, 지도에서 아파트 마커를 누르면
그 단지의 장단점을 **거주 후기 요약**과 **공공데이터 정량 지표** 두 겹의 근거로
한 화면에서 볼 수 있게 하는 단일 페이지 웹앱.

- 런타임에 외부 API를 호출하지 않는다. 수집·요약은 개발 중 **배치로 1회** 실행하고
  결과를 정적 `data.json` 하나로 번들한다.
- 정량 장단점은 **규칙(사분위)** 으로 만든다. LLM은 후기의 **광고 분류**와 **항목별 요약**에만 쓴다.
- 지도는 **OpenStreetMap(Leaflet)** 을 쓴다. **프론트에 남는 API 키가 하나도 없다.**

---

## 1. 지금 바로 확인하기 (키 없이)

```bash
# 1) 데모 데이터 생성 (실제 단지가 아닌 예시 14개 단지)
pip install -r scripts/requirements.txt
python scripts/make_mock.py

# 2) 프론트 실행
cd web
npm install
npm run dev        # http://localhost:5173
```

지도 키를 발급받을 필요가 없다. 바로 OpenStreetMap 지도가 뜨고 마커가 찍힌다.
데모 데이터일 때는 화면 상단에 보라색 경고 배너가 뜬다.

## 3. 데이터 파이프라인

### ① `base.py` — 정량 (LLM 미사용)

1. **단지 목록** — 빛가람동 법정동코드(`1217013400`)로 K-apt 단지목록 API를 호출한다.
   실패하면 나주시 시군구코드(`12170`)로 받아 주소에 `빛가람동`이 들어가는 것만 거른다.

   > **주의 — 지역코드가 바뀌었다.** 2026년 전라남도·광주광역시가
   > **'전남광주통합특별시'** 로 통합되면서 시도 코드가 46(전남)/29(광주) → **12** 로
   > 바뀌었다. K-apt 데이터는 이미 새 코드로 갱신돼 있어서, 옛 코드(46170)로 부르면
   > 인증도 통과하고 `resultCode: 00 NORMAL SERVICE` 가 오는데 **결과만 0건**으로
   > 나온다. 에러가 아니라 빈 응답이라 원인을 찾기 까다로우니 주의할 것.
   > (실측: 서울·경기·부산·제주·충남은 옛 코드로도 정상, 전남·전북·광주만 0건)
2. **기본정보 + 상세정보** — 세대수·동수·연면적·난방방식·경비 인원·주차 대수·편의시설.
3. **공용관리비** — '총액을 한 번에 주는' 오퍼레이션은 **존재하지 않는다.** 인건비·
   청소비·경비비·승강기유지비·수선비·위탁관리수수료 등 **17개 항목이 전부 별도
   오퍼레이션**이라, 단지·월마다 17번 호출해서 직접 합산한다
   (`config.COST_CATEGORIES`). 그 값을 관리비부과면적으로 나눠 **㎡당 원**으로 만든다.
   - 17개는 서로 독립적인 GET 이라 **병렬로 호출**한다 (순차로 하면 단지당 8초).
   - 한 항목이라도 **호출에 실패하면 그 달은 통째로 버린다.** 일부만 더하면 총액이
     과소 계산돼, 같은 데이터인데도 실행할 때마다 사분위 판정이 달라진다.
4. **실거래가** — 나주시 최근 12개월 아파트 매매를 받아 단지명으로 매칭한다.
5. **좌표** — `data/coords.json`(수동) → VWorld 지오코더 → OSM Nominatim 순으로 1회 조회해
   JSON에 고정한다. 런타임 지오코딩은 하지 않는다. 못 찾은 단지는 콘솔에 나열되고
   `data/coords.missing.json` 템플릿이 만들어진다.
6. **판정** — 항목별로 동 내 분포를 만들고 사분위로 자른다.

| 항목 | 지표 | 방향 |
|---|---|---|
| 주차 | 세대당 주차대수 | ↑ 장점 |
| 관리비 | ㎡당 공용관리비 | ↓ 장점 |
| 보안·관리 | 경비원 1명당 세대수 | ↓ 장점 |
| 규모 | 세대수 | ↑ 장점 |
| 노후도 | 준공년도 | ↑ 장점 |
| 교통·생활편의 | 기본정보의 편의·교육시설 항목 수 | ↑ 장점 |

- 상위 25%(Q3) **밖**이면 장점, 하위 25%(Q1) **밖**이면 단점, 중간 50%는 카드를 만들지 않는다.
- 표본이 6개 단지 미만인 항목은 판정하지 않는다. 값이 없으면 `자료 없음` 으로 표시한다.
- 화면에는 판정 근거(동 평균, Q1/Q3 경계, 순위)를 항상 같이 적는다.

### ② `collect.py` — 후기 원문 수집

- **Tavily 검색 API**: 단지당 4회 검색(= 4 크레딧). 검색어 4개 변형
  (`빛가람동 OO 아파트 거주 후기`, `OO 실거주 장단점`, `OO 관리비`, `OO 주차`).
  - 결과의 `content`(질의 관련 발췌)만 저장하고 `raw_content`(페이지 전문)는 요청하지 않는다.
    원문을 통째로 복제하지 않기 위해서다.
  - `--community-pass` 를 주면 카페·블로그 도메인 한정 검색 2회를 추가한다(기본 꺼짐).
    **실측상 네이버 카페는 로그인 벽 때문에 도메인 한정 검색에서 0건이 나온다.**
    반대로 일반 웹 검색에서는 `blog.naver.com` 글이 가장 많이 잡힌다.
- **2단 필터** — LLM에 넘기기 전에 코드로 먼저 거른다.
  1. `config.IRRELEVANT_DOMAINS` — 주소만 같은 숙박·예약·SNS 사이트 제외.
  2. `TOPIC_HINTS` — 제목+발췌에 거주 관련 어휘(후기·관리비·주차·층간소음 등)가
     하나도 없으면 버린다.
- **아파트 리뷰 전문 플랫폼(호갱노노 등)은 기본으로 검색 대상에 포함한다.** 실거주
  후기가 가장 잘 쌓여 있는 곳이라서다. Tavily의 공개 색인에서 제목·발췌·링크만
  받아 오는 것이라 직접 크롤링과는 다르다고 보았다. 더 보수적으로 가고 싶다면
  `--exclude-review-platforms` 로 `config.REVIEW_PLATFORM_DOMAINS` 목록을 검색에서
  뺄 수 있다 (아래 6-3-1 참고). 포함되는 글은 화면에 `리뷰 플랫폼` 출처로 표시된다.
- **배분 규칙**: 남은 문서 중 제목+발췌에 **단지명이 있으면 그 단지로**,
  **동 이름만 있으면 `동 전체` 버킷으로** 넣는다. 유튜브 댓글과 똑같은 규칙이다.
  중복 제거는 URL을 정규화해서(`m.`/`www.` 접두사, 끝 슬래시 제거) 한다 —
  같은 글이 `blog.naver.com` 과 `m.blog.naver.com` 으로 두 번 잡히는 일이 잦다.
- **유튜브 Data API (P1)**: `search.list` 로 지역 영상을 찾고 `commentThreads.list` 로
  댓글을 모은다. 댓글 본문에서 단지명이 확인되는 것만 해당 단지에 배분하고,
  나머지는 `동 전체` 버킷에 넣어 지역 공통 특징으로만 쓴다.
- 이 단계는 저장만 한다. 분류·요약은 하지 않는다.

### ③ `summarize.py` — 광고 분류 → 항목별 요약 → 병합

1. **분류가 먼저다.** 각 문서를 `ad`(광고·분양홍보) / `review`(실거주 후기) /
   `unrelated` 로 나눈다. 애매하면 광고로 분류하도록 프롬프트에 못 박았다.
2. `review` 로 분류된 것만 6개 항목으로 묶고, **근거가 3건 이상인 항목만** 요약한다.
3. 문장은 `"일부 후기에서 ~라는 언급이 있음"` 형태로만 만든다. 원문은 재현하지 않는다.
4. 모델이 돌려준 근거 id를 **코드에서 다시 검증**한다. 실제 후기 문서가 아니거나
   그 항목을 언급하지 않은 id는 버리고, 남은 개수가 3건 미만이면 그 요약은 폐기한다.
5. `base.json` 에 병합해 `data.json` 을 쓰고 `web/public/data.json` 으로 복사한다.

모델은 `claude-opus-5`, 출력은 JSON Schema로 고정(structured outputs), 정책 거절 시
서버측 폴백을 켜 뒀다. `--no-llm` 을 주면 정량만으로 `data.json` 을 만든다.

## 4. 화면

- **지도** — 빛가람동 중심 고정, 단지 마커 + 단지명 라벨.
  마커 색으로 근거 상태 구분(파랑 = 후기+정량 / 회색 = 정량만). 후기 없는 단지도 숨기지 않는다.
- **좌측 상단** — 서비스명, 대상 지역, 데이터 기준일.
- **우측 하단** — 범례, 면책 문구, 동 전체 이야기.
- **단지 패널** (마커 클릭)
  - 상단: 단지명·주소·준공년도·세대수/동수·난방방식·최근 실거래가
  - 중단: 6개 항목이 한 줄씩. 장점/단점 배지 → 정량 근거 문장 → 정성 근거 문장 →
    근거 건수 → 사분위 기준 → `근거가 된 글 N건 보기`(제목 + 원문 링크만)
  - 하단: 수집 N건 / 광고 제외 N건 / 요약 근거 N건, 정량 출처와 기준월, 판정 규칙, 면책 문구
- 후기가 없는 단지는 정성 자리에 `유효 후기 3건 미만으로 요약을 만들지 않았습니다` 를 표시한다.
- **본문·댓글 원문은 어떤 경우에도 화면에 옮기지 않는다.**

## 5. 실제 데이터로 돌리기

```bash
cp .env.example .env      # 키 채우기 (아래 6장 참고)
pip install -r scripts/requirements.txt

python scripts/run_all.py             # ①②③ 순서 실행
# 또는 개별로
python scripts/base.py --limit 3      # 먼저 3개 단지로 응답 확인
python scripts/collect.py --no-youtube   # Tavily 수집 (유튜브 생략)
python scripts/summarize.py --limit 3
```

`run_all.py` 는 ②나 ③이 실패해도 ①의 정량 데이터만으로 `data.json` 을 만들고 끝낸다.

### 실행 시간과 캐시

①은 단지 하나당 **관리비 17회 + 기본/상세 2회 + 좌표 1회**를 호출한다. 빛가람동
19개 단지 기준 **처음 실행은 약 2분**이 걸린다 (공공데이터 API 1회 왕복 ≈ 0.25초,
OSM Nominatim 은 이용 정책상 요청마다 1.1초를 쉬어야 한다).

응답은 `data/.api_cache.json` 에 캐시되므로 **재실행은 약 10초**다. 공공데이터는
월 단위로만 갱신되니 그대로 재사용해도 안전하다.

```bash
python scripts/base.py              # 캐시 사용 (빠름)
python scripts/base.py --refresh    # 캐시 무시하고 전부 새로 받기
rm data/.api_cache.json             # 캐시 통째로 비우기
```

진행 중에는 단지마다 경과 시간과 남은 예상 시간이 표시되고, 단지 하나가 끝날 때마다
캐시를 저장하므로 **중간에 끊어도 거기까지 받은 건 다음 실행에서 재사용**된다.

**품질 점검(기획서 항목):** 요약이 나오면 3~4개 단지를 골라 `근거가 된 글 보기` 의
링크를 직접 열어보고, 광고가 후기로 섞였는지 확인한다. 섞였다면
`scripts/summarize.py` 의 `CLASSIFY_SYSTEM` 프롬프트를 조이고 ③만 다시 돌린다.

## 6. 사용자가 직접 해야 하는 일 (API 키 발급)

| # | 키 | 발급처 | 쓰는 곳 | 필수 |
|---|---|---|---|---|
| 1 | 공공데이터 인증키 | data.go.kr | ① base.py | **필수** |
| 2 | VWorld API 키 | vworld.kr | ① base.py (좌표) | 권장 (없으면 OSM 사용) |
| 3 | Tavily API 키 | app.tavily.com | ② collect.py | 후기 기능에 필요 |
| 4 | 유튜브 Data API v3 | console.cloud.google.com | ② collect.py | 선택 (P1) |
| 5 | Claude API 키 | console.anthropic.com | ③ summarize.py | 후기 요약에 필요 |

**지도 키는 필요 없다.** OpenStreetMap 타일을 직접 쓰기 때문에 프론트에는 키가 하나도 없다.

### 6-1. 공공데이터포털 (data.go.kr)

로그인 후 아래 **4개 서비스를 각각 활용신청**한다. 승인은 보통 자동/수 분 이내다.

1. 국토교통부_공동주택 단지 목록제공 서비스
2. 국토교통부_공동주택 기본 정보제공 서비스
3. 국토교통부_공동주택관리비(공용관리비)정보제공서비스
4. 국토교통부_아파트 매매 실거래가 자료

마이페이지 → 인증키의 **일반 인증키(Decoding)** 값을 `.env` 의 `KAPT_SERVICE_KEY` 에 넣는다.
(Encoding 값을 넣으면 이중 인코딩으로 인증에 실패한다.)

**엔드포인트는 이미 최신 버전으로 넣어 두었다.** `scripts/config.py` 의 `ENDPOINTS` 한 곳에만 있다.

```python
ENDPOINTS = {
    "apt_list":  "https://apis.data.go.kr/1613000/AptListService4",
    "apt_basis": "https://apis.data.go.kr/1613000/AptBasisInfoServiceV5",
    "apt_cost":  "https://apis.data.go.kr/1613000/AptCmnuseManageCostServiceV3",
    "apt_trade": "https://apis.data.go.kr/1613000/RTMSDataSvcAptTradeDev",
}
```

오퍼레이션 이름(`getSigunguAptList4`, `getAphusBassInfoV5` …)은 서비스 주소 끝의 버전
표기를 그대로 따라가는 규칙이라 `kapt_api.py` 가 **후보를 만들어 처음 성공하는 것을
자동으로 고른다.** 실제로 어떤 주소가 쓰였는지는 실행 로그와 `base.json` 의
`sources.endpoints` 에 남는다. 나중에 버전이 또 올라가면 위 4줄만 바꾸면 된다.

> 실거래가 서비스 주소는 확인받지 못해 기존 값을 그대로 두었다. 다르면 `apt_trade`
> 한 줄만 고치면 된다. 이 항목이 실패해도 '최근 실거래가'만 비고 나머지는 정상 동작한다.

### 6-2. 좌표 — VWorld (권장) 또는 OSM Nominatim (키 없음)

지도 자체는 키가 필요 없지만, **단지 좌표는 배치에서 한 번 구해 넣어야** 마커가 찍힌다.

- **VWorld** (국토교통부 공간정보 오픈플랫폼, 무료) — [vworld.kr](https://www.vworld.kr)
  회원가입 → 오픈API → 인증키 발급 → `.env` 의 `VWORLD_API_KEY`.
  한국 도로명/지번 주소 정확도가 가장 좋아 이걸 권한다.
- **넣지 않으면** OSM Nominatim으로 조회한다. 키는 필요 없지만 국내 아파트 주소
  적중률이 떨어지고, 이용 정책상 초당 1회로 제한해 단지당 1초 정도 걸린다.

좌표를 못 찾은 단지는 실행 후 콘솔에 이름·주소가 나열되고
`data/coords.missing.json` 템플릿이 만들어진다. 지도에서 좌표를 찾아 채운 뒤

```bash
mv data/coords.missing.json data/coords.json   # lat/lng 를 채운 후
python scripts/base.py --geocode-only
python scripts/summarize.py --no-llm           # data.json 에 반영
```

좌표가 없는 단지도 **목록에서 사라지지 않는다.** 범례의 `좌표 없음 N` 버튼에서
눌러 패널을 열 수 있다.

### 6-3. Tavily (app.tavily.com)

가입 → API Keys → 키 발급 → `.env` 의 `TAVILY_API_KEY`.
**신용카드 없이 월 1,000 크레딧**이 무료다.

- basic 검색 1회 = 1 크레딧. 이 배치는 **단지당 4크레딧**(`--community-pass` 시 6)을 쓴다.
- 단지 30개면 1회 실행에 **약 120크레딧** — 무료 한도로 한 달에 8번 정도 돌릴 수 있다.
- 크레딧이 떨어지면(HTTP 429) 남은 검색을 건너뛰고 그때까지 모은 결과로 계속 진행한다.
- 실제 사용량은 실행 로그와 `reviews_raw.json` 의 `stats.tavilyCredits` 에 기록된다.

**실측 (2026-09-03, 실제 단지 2곳):** 단지당 4회 검색으로 필터 통과 7~19건이 모였고,
출처는 `blog.naver.com` 이 가장 많았다. 광고·매물 글이 상당수 섞여 들어오지만
그것을 걸러내는 것이 ③의 첫 단계다.

> **왜 SerpAPI가 아니라 Tavily인가:** SerpAPI 무료 한도는 월 100회 검색이라
> 단지 30개(120회)를 한 번도 다 못 돌린다. Tavily는 1,000크레딧이라 여유가 있고,
> 응답이 단순 스니펫이 아니라 질의에 맞춘 발췌라서 ③의 광고 분류 정확도가 올라간다.
> 신용카드도 필요 없다.
>
> **한계:** 네이버 카페는 로그인 벽 때문에 어떤 검색 API로도 색인되지 않는다.
> 기획서의 '카페글 우선' 은 현실적으로 달성이 어렵고, 실제로는 네이버 블로그가
> 주된 출처가 된다. 지역 커뮤니티 사이트를 알고 있다면 `COMMUNITY_DOMAINS` 에
> 추가하고 `--community-pass` 로 돌리는 편이 낫다.

### 6-3-1. 리뷰 전문 플랫폼 — 기본값은 포함

기획서 초안은 아파트 리뷰 전문 플랫폼(호갱노노 등)을 '쓰지 않는 데이터'로 뒀지만,
이 프로젝트는 그 플랫폼을 직접 크롤링하지 않고 **Tavily 검색 API의 공개 색인에서
제목·발췌·링크만 받아 온다** — 화면에도 원문이 아니라 AI 요약과 링크만 노출된다.
그 판단에 따라 **기본값은 이 플랫폼들도 검색 대상에 포함**한다. 실거주 후기가
가장 잘 쌓여 있는 곳이라 후기 수집량과 품질이 눈에 띄게 좋아진다.

- 더 보수적으로 가고 싶다면 `python scripts/collect.py --exclude-review-platforms`
  로 `config.REVIEW_PLATFORM_DOMAINS` 목록을 검색에서 뺄 수 있다.
- **법적 위험이 완전히 0은 아니다.** 저작권법 93조는 개별 소재가 '상당한 부분'에
  못 미쳐도 **반복적이거나 체계적으로** 추출해 데이터베이스의 정상 이용을 해치면
  상당한 부분의 복제로 본다는 조항을 따로 두고 있다(관련 판례: 특허법원 2025.12).
  단지 수십 개에 대해 반복적으로 같은 사이트를 겨냥해 쿼리를 던지는 이 프로젝트의
  수집 패턴이 그 조항의 적용 대상이 될 가능성 자체는 남아 있다. 다만 개인·학습
  목적의 소규모 트래픽에서 실제로 문제가 될 가능성은 낮다고 보고 기본값을
  '포함'으로 두었다 — 이 판단이 부담스럽다면 위 옵션으로 언제든 뒤집을 수 있다.
- **도메인 차단(옵션을 켰을 때)은 최선의 노력일 뿐이다.** 실측에서 목록에 없던
  유사·오타 도메인이 섞여 들어왔다. 수집 후 `reviews_raw.json` 의 도메인 분포를
  한 번 훑어보고 새로 보이는 곳을 목록에 추가하는 식으로 관리해야 한다.
- 포함된 글은 화면과 근거 목록에 `리뷰 플랫폼` 출처로 구분 표시된다.

### 6-4. 유튜브 Data API v3 (선택, P1)

Google Cloud Console → 프로젝트 생성 → **YouTube Data API v3** 사용 설정 →
사용자 인증 정보에서 **API 키** 발급 → `.env` 의 `YOUTUBE_API_KEY`.

무료 쿼터는 하루 10,000 units이고 `search.list` 는 **호출당 100 units** 로 비싸다.
`collect.py` 는 기본값으로 search 6회(600) + 댓글 12회(12) 정도만 쓴다.
쿼터가 걱정되면 `--no-youtube` 로 통째로 생략해도 서비스는 성립한다.

### 6-5. Claude API (console.anthropic.com)

API 키를 만들어 `.env` 의 `ANTHROPIC_API_KEY` 에 넣는다.
`summarize.py` 는 단지당 분류 호출 몇 번 + 요약 1번을 쓴다.
단지 25~30개, 단지당 후기 100건 안팎이면 **1회 실행에 대략 $2~5** 수준이다.
`--limit 3` 으로 먼저 소량 실행해 결과와 비용을 확인한 뒤 전체를 돌리는 것을 권한다.

## 7. 배포 (Vercel)

1. 이 폴더를 GitHub 저장소로 올린다. (`.env` 는 `.gitignore` 로 빠진다.
   `web/public/data.json` 은 **반드시 커밋해야 한다** — 배포본의 데이터가 이 파일이다.)
2. Vercel → New Project → 저장소 선택
   - **Root Directory**: `web`
   - Framework Preset: Vite (자동 인식)
   - Build Command: `npm run build` / Output Directory: `dist`
3. **환경변수 설정은 없다.** 지도 키가 없으므로 Vercel에 넣을 값이 하나도 없다.
   그대로 Deploy만 누르면 된다.

> 지도 타일은 OpenStreetMap 공개 타일 서버(`tile.openstreetmap.org`)를 쓴다.
> 개인·소규모 서비스는 무료지만 [타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)이
> 있고, 화면에 저작자 표시(`© OpenStreetMap 기여자`)를 반드시 남겨야 한다 —
> 지도 좌하단과 면책 팝업에 넣어 두었으니 지우지 말 것.
> 트래픽이 커지면 MapTiler·Stadia Maps 등 OSM 기반 타일 제공자로 URL만 바꾸면 된다
> (`web/src/components/MapView.jsx` 의 `TILE_URL`).

데이터를 갱신할 때는 배치를 다시 돌리고 `web/public/data.json` 을 커밋·푸시하면 된다.
백엔드도 서버리스 함수도 없다.

## 8. 다른 지역으로 확장

`scripts/config.py` 의 `REGION` 만 고치면 된다.

```python
REGION = {
    "sido": "전남광주통합특별시", "sigungu": "나주시", "dong": "빛가람동",
    "sigungu_code": "12170",              # 실거래가 LAWD_CD 로도 쓴다
    "bjd_code": "1217013400",             # 빛가람동 법정동코드 10자리
    "center": {"lat": 35.0208, "lng": 126.7900},
    "zoom": 14,
}
```

`center` 는 Leaflet 지도의 초기 중심, `zoom` 은 Leaflet 줌 레벨(클수록 확대, 동 단위는 14 전후)이다.
`collect.py` 의 유튜브 검색어 목록도 지역명에 맞게 바꿔주면 좋다.

**지역코드를 확인하는 가장 확실한 방법:** K-apt 사이트(k-apt.go.kr)에서 단지를 이름으로
검색하면, 결과 목록의 `<li>` 에 `data-kaptcode` 와 `knew_createForm('<법정동코드>', ...)`
가 그대로 들어 있다. 위 코드도 그렇게 확인했다 — 검색 결과로 나오는 코드를 쓰면
행정구역이 또 개편돼도 헤매지 않는다.

## 9. 설계상 지킨 선

- 후기 **원문(본문·댓글)은 화면에 옮기지 않는다.** 요약과 제목·링크만 보여준다.
- 표현은 `"일부 후기에서 ~라는 언급이 있음 (근거 N건)"` 형태로만 만든다. 단정하지 않는다.
- 근거 건수 · 원문 링크 · 면책 문구 · 사분위 기준 표기는 **어떤 경우에도 빼지 않는다.**
- 아파트 리뷰 전문 플랫폼은 **직접 크롤링하지 않는다.** Tavily 검색 API의 공개
  색인에서 제목·발췌·링크만 받아 오고 기본값으로 검색 대상에 포함한다(6-3-1 참고).
  저작권법상 데이터베이스제작자 권리(93조, 반복적·체계적 수집 조항)를 완전히
  배제하지는 못하지만, 소규모 트래픽에서의 위험은 낮다고 보고 내린 선택이다.
  `--exclude-review-platforms` 로 언제든 더 보수적인 기본값으로 되돌릴 수 있다.
- 공공데이터·VWorld·Tavily·유튜브·Claude 키는 전부 배치 스크립트에만 있고 배포본에 포함되지 않는다.
  **배포된 프론트에는 API 키가 하나도 없다.**
- 지도 데이터 © OpenStreetMap 기여자 (ODbL). 저작자 표시를 화면에서 제거하지 않는다.
